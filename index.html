The hard part is the proof

An AI agent asks its model many small questions per conversation: which tool to use, what to fill in, what to reply. Many are routine, and a small model can answer them for a fraction of the cost. The hard part is proving which ones it can take over. Four things make that easy to get wrong:

Calls in a conversation are linked

One confusing conversation causes many mistakes at once. Counting each call as separate evidence gave a wrong approval in up to half of our test runs.

People check results every day

Re-checking until the numbers look good is like flipping a coin until it lands heads: false approvals rose from 5% to 12%.

There's often more than one right answer

Answering differently from the big model isn't always answering worse, and some checks can't tell the two apart.

The answer key has mistakes

If the grader misses errors, the small model looks better than it is. Uncorrected, it gave a wrong approval in up to every test run.

How it works

Bring your traces and a candidate, ask the candidate every held-out call, and grade it per slice of traffic.

01 · Ingest

One schema for any trace

Converters for OpenAI tool_calls, function_call, Hermes, Toucan, Nemotron, SWE-rebench and τ²-bench, plus tool calls written into the text. Every repair is audited.

02 · Compare

Any candidate you can serve

Time-ordered split by session. The candidate, behind any OpenAI-compatible endpoint, answers the same held-out calls the big model did. Hosting stays yours.

03 · Graduate

A report card per slice

Slices are agent node × call type × tool × position. Each gets an exact bound on its disagreement with the big model and the share of calls and tokens it covers.

  1. Bring your logs. The conversations your agent already had with its big model.Converters for OpenAI tool_calls, function_call, Hermes, Toucan, Nemotron, SWE-rebench, τ²-bench and tool calls written into the text; every repair is recorded.
  2. Cut them into slices. A slice is one kind of decision, like "look up a reservation at the start of a chat".Slice = agent node × call type (tool or text) × tool × position bucket in the session.
  3. Split by time. Older conversations are yours to tune on; newer ones test. The test set is never tuned on, and never reused.graduate certify certifies the whole file you give it, so pass only newer conversations. In Python, split_sessions makes the time-ordered split by session.
  4. Bring a candidate. Any cheaper model: an open model you serve, a cheaper API, or one you built yourself.Any OpenAI-compatible endpoint (--base-url, --model).
  5. Compare on new conversations. The candidate answers the same held-out calls the big model did; Graduate counts where they differ.Gates: disagreement and invalid call (the Python report card takes any gates you define). Per-session counts under a router cap.
  6. Get a verdict per slice. Each slice graduates, needs more evidence, or stays with the big model, plus how much traffic and cost that covers.Anytime-valid betting test per slice, Benjamini–Hochberg across slices, δ = 0.05.

The statistics are checked before they're trusted

Every adopted method held its promised 5% false-certification rate in every simulation grid and on a week of real agent traffic (197k tool calls) used as a population with exact truth. Common shortcuts did not.

How often each method wrongly certifies a slice

Worst rate seen across all tests, log scale. A method is safe if its bar stops at the 5% line (shaded band: simulation noise).

In one sentence

Graduate makes a promise: when it says "this part of the work is safe to hand to the small model", it is wrong at most 5 times out of 100. This chart checks whether that promise holds, and shows that the usual shortcuts break it.

An everyday picture

Think of a building inspector who promises to sign off on an unsafe building no more than 1 time in 20. You can't trust that promise by reading the inspector's method. You test it: build many buildings that are just barely unsafe, send the inspector, and count how often they sign off anyway. If it's 1 in 20 or less, the promise holds. If it's 1 in 2, it doesn't.

How we tested it
  1. 1Build a test worldwhere the small model's real error rate is exactly 5%: just over the line, the hardest case to catch
  2. 2Run the checkon conversations drawn from that world, exactly as it would run on real traffic
  3. 3Did it say "safe"?That's a wrong certification. Count it.
  4. 4Repeat 1,000 timesThe share of wrong "safe" verdicts is the bar in the chart

We did this on made-up data with many different shapes, and on a real week of agent traffic (197k tool calls) where we knew the right answers. Bar stops at the line: the promise holds. Bar crosses the line: the promise is broken.

Go deeper still: the technical definition

What is measured. For a slice with true per-call error p and claim p ≤ α (α = 5%), a false certification is a certificate issued when p ≥ α. Each bar is the worst observed P(certify | p = α) over all simulation settings: the boundary null, where a valid test is hardest to keep valid. With many slices it is the family-wise error rate.

The band. Each rate comes from 1,000 replications, so a true 5% shows up anywhere up to about 5% + 2·√(0.05·0.95/1000) ≈ 6.4%. The shaded band is that Monte Carlo tolerance.

Settings covered. Session random effects σ ∈ [0, 3] on the logit scale, 3–30 calls per session, 5–80 slices, cross-slice correlation up to 0.9, and a public week of real agent traffic (197k tool calls) used as a finite population with exact truth.

The betting test. With per-session statistic Xi = errorsi − α·acceptedi, the capital Kt = ∏(1 − λiXi), with predictable bets λi ∈ [0, c/U], is a non-negative supermartingale under H₀: E[X] ≥ 0. Ville's inequality gives P(supt Kt ≥ 1/δ) ≤ δ, so p = 1/max K is valid at every look. Graduate averages bettors over c ∈ {0.5, 0.75, 0.9, 0.99}.

Across slices. Benjamini–Hochberg at δ = 0.05 by default. The full validity report will be published in a later release.

Proof needs conversations

Minimum test conversations to prove an error rate is below the limit, even if the model makes zero mistakes (95% confidence, one slice).

Covering more traffic costs more evidence

Real agent traffic: chance of certifying a slice that truly is 1 point under the limit. Each line lets the small model handle a different share of calls.

Where it stands

Honest results so far: the statistics work. The candidates we have tested either aren't accurate enough yet, or there aren't enough test conversations to prove they are. Each verdict was pre-registered before the run.

How to read a verdict

Each result answers one question: how much of the traffic could we hand to the small model, with proof that it gets at most 5% of those calls wrong?

X% certified

X% of real calls could go to the small model. For those calls we are 95% sure its error rate is at most 5%.

Nothing certified at 5%

We could not prove the 5% limit for any slice of traffic, so every call stays with the big model. It does not mean the small model is wrong 95% of the time.

Not graduated

The final end-to-end test of the mixed system (small + big model) didn't pass both of its bars: no worse than the big model alone, and useful (the small model handles at least 10% of turns).

Example. On a slice where the small model made 0 mistakes in 95 conversations, that sounds safe. But with 7 slices tested at once, 95 conversations is still too few to rule out a 5% error rate, so it isn't certified. Roughly three times more test conversations would likely certify it.

Built

  • Statistics library (graduate.certify), typed, tested
  • One trace schema and converters for seven formats
  • Report card and the graduate certify command line

Next

  • Outcome-based certification on replayable environments
  • Larger held-out sets, so more slices can be decided
  • Shadow mode with a restarting drift detector

Why nothing graduated yet: evidence, not the model, is the bottleneck. At a 3–5% claim a slice needs hundreds to ~1,000 independent sessions. See the experiments overview for what is running.

Use it from Python

Each example builds on the one before, from loading logs to the statistics underneath.

Install: pip install "git+https://github.com/nstream-ai/graduate.git", then graduate certify traces.jsonl --base-url <candidate endpoint> --model <candidate>. No model yet? examples/mock_candidate.py is a stand-in, and a small model on your CPU via Ollama or llama.cpp works too (see examples/README.md). Code, docs and the report template are on GitHub.

1 · Load your agent's logs

Turn a JSONL file of chat logs into conversations. Each line is one conversation in OpenAI chat format (messages, optional tools). Other formats: see trace formats in the README.

from graduate.ingest import ingest, report
from graduate.core import slice_of

sessions = list(ingest("traces.jsonl", preset="openai"))
print(report(sessions))          # calls, tool calls, repairs, missing context

s = sessions[0]
for call in s.calls:
    print(slice_of(s, call))
# agent/tool/get_reservation_details/1
# agent/text/-/2-3
2 · Split by time

Older conversations are yours to tune on; newer ones are kept aside to judge the candidate.

from graduate.core import split_sessions

split = split_sessions(sessions)   # train 70% / dev 10% / calibration 20%, by time when timestamps exist
train, dev, held_out = split["train"], split["dev"], split["calibration"]
3 · Get the report card

Give it one row per held-out call: which slice it's in, which conversation it came from, and whether the small model disagreed with the big one. Rows go in arrival order.

from graduate.certify.card import report_card

card = report_card(
    slice_keys,     # e.g. "support/tool/get_reservation_details"
    session_ids,    # conversation id of each call
    wrong=disagree, # True where the small model differs from the big model
    alpha=0.05,     # the promise: at most 5% of handed-over calls wrong
    delta=0.05,     # ...with 95% confidence
    cap=5,          # the small model takes at most 5 calls per conversation
)
print(card.render())

4 · One slice, by hand

The building blocks. Zero mistakes in 95 conversations: how sure can we be that the error rate is under 5%?

from graduate.certify.stats import clopper_pearson_upper, risk_pvalue

clopper_pearson_upper(errors=0, n=95, delta=0.05)  # 0.031: error is at most 3.1%
risk_pvalue(errors=0, n=95, alpha=0.05)          # 0.0077: passes alone, but not after
                                                  # correcting for 7 slices tested at once
5 · Check every day without breaking the promise

For shadow mode, where you look at results as they arrive. Inputs are per-conversation counts: mistakes, and calls the small model handled.

from graduate.certify.stats import betting_risk_test

test = betting_risk_test(
    errors=errors_per_session, accepted=handled_per_session,
    alpha=0.05, cap=5, c=(0.5, 0.75, 0.9, 0.99),
)
test.pvalue        # valid however many times you've looked
test.capital       # the evidence path, one value per conversation
6 · How many more conversations?

Plan before you collect. A slice with about 2% errors, which the small model handles in 40% of conversations, with 300 collected so far:

from graduate.certify.stats import plan_evidence

plan_evidence(risk_estimate=0.02, coverage=0.4, sessions_collected=300, alpha=0.05)
